# Chapter 10 — Sessions, Compaction & Memory

Expert: **Runtime/Loop Expert**. Sources: `pkg/session/`, `pkg/compaction/`, `pkg/runtime/*compaction*.go`, `pkg/memory/`, `pkg/paths/`, `docs/features/sessions`.

## Session store (`pkg/session`)

- **SQLite-backed** persistence (`store.go` + `sqliteutil` + migrations) under per-user data dir from `pkg/paths`.
- Stores: messages (with agent attribution), tool calls/results, routing decisions, think scratchpad, generated-media manifest, session metadata (title, usage, cost), per-session working directory pointer.
- **Branching** (`branch.go`) and **forking** (exposed via REST API) — explore alternate conversations from any point.
- Read-only sessions (resumed elsewhere or shared) enforced at store level; `docker agent sessions` browses/diffs/resumes — including resuming into a fresh git worktree.
- The runtime's **PersistenceObserver** subscribes to the event stream and writes session-scoped events only (sub-session noise filtered via the `SessionScoped` marker).

## Compaction — keeping the window bounded

Multiple cooperating mechanisms:

| Mechanism | Trigger | Where |
|-----------|---------|-------|
| **Proactive compaction** | history exceeds `compaction_threshold` fraction of context window | `runtime/compaction_controller.go`, `session_compaction.go`; uses dedicated `compaction_model` |
| **Post-overflow recovery** | provider returns context-length error | auto-summarize + retry → `SessionRecoveredEvent` |
| **Native compaction** | provider-side (e.g., Claude server-side compaction) | `native_compaction.go` |
| **Background compaction** | idle time, off critical path | `background_compaction.go` |
| **Middle-out truncation** | single oversized tool result | `max_tool_result_tokens` (~len/4 token estimate) keeps head+tail |
| **Old tool-call pruning** | accumulated stale results | `max_old_tool_call_tokens` |
| **History window** | simple cap | `num_history_items` |

Hook integration: `pre_compact` / `before_compaction` (can veto or supply custom summary) / `after_compaction` — users can inject their own summarization policy or models.

Compaction emits `SessionCompactionEvent` with before/after token counts so UIs show savings.

## Prompt-cache economics (ties everything together)

The design obsession visible across Ch. 5 + this chapter: **the instruction prefix is frozen**; dynamic content (memories, date, env info, steering) is *appended*, deferred tools materialize lazily, `pkg/cache` memoizes responses. Result: maximal provider cache hits, lower cost, faster first-token.

## Memory

- Builtin `memory` toolset (`pkg/tools/builtin/memory` + `pkg/memory`): persistent key-value notes surviving across sessions; agents instructed when to save/read.
- `sessioncontext` toolset lets an agent read *other* sessions' histories — cross-conversation awareness without polluting current context.
- Session titles auto-generated by cheap `titleModel` (`pkg/sessiontitle`) shown in the browser.
